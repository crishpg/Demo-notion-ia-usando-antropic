Sobre o Projeto

O Sistema Para Freelancers é uma aplicação web completa para gerenciar clientes, projetos e atividades, com design inspirado no Notion. Desenvolvida com Next.js App Router, TypeScript e PostgreSQL.

  • CRUD completo de clientes, projetos e atividades
  • Dashboard com estatísticas em tempo real via API
  • Rastreamento de prazos e alertas de deadline
  • Sistema de prioridades para atividades
  • Interface responsiva inspirada no Notion (dark mode)
  • API REST com Next.js Route Handlers + node-postgres
  • Deploy automatizado via Docker e script quickstart
  • Autenticação de usuários (planejado)
  • Sincronização com Notion (planejado)

API Routes REST

/api/clientes

MétodoBodyRetorno
GET—Array de clientes ordenados por nome
POST{ nome, email?, telefone?, instagram?, drive? }Cliente criado (201)
PUT{ id, nome, email?, telefone?, instagram?, drive? }Cliente atualizado
DELETE{ id }{ ok: true }

/api/projetos

MétodoBodyRetorno
GET—Array com cliente_nome via JOIN
POST{ nome_projeto, cliente_id?, data_inicio?, data_fim?, status, lancado }Projeto criado (201)
PUT{ id, nome_projeto, cliente_id?, data_inicio?, data_fim?, status, lancado }Projeto atualizado
DELETE{ id }{ ok: true }

/api/atividades

MétodoBodyRetorno
GET—Array com nome_projeto e cliente_nome via JOIN
POST{ nome, projeto_id?, status, prioridade?, data_inicio?, data_fim? }Atividade criada (201)
PUT{ id, nome, projeto_id?, status, prioridade?, data_inicio?, data_fim? }Atividade atualizada
DELETE{ id }{ ok: true }

Testar via curl

# Listar clientes
curl http://localhost:3000/api/clientes

# Criar cliente
curl -X POST http://localhost:3000/api/clientes \
  -H "Content-Type: application/json" \
  -d '{"nome":"João Silva","email":"joao@exemplo.com"}'

# Editar cliente
curl -X PUT http://localhost:3000/api/clientes \
  -H "Content-Type: application/json" \
  -d '{"id":"UUID-AQUI","nome":"João Editado"}'

# Excluir cliente
curl -X DELETE http://localhost:3000/api/clientes \
  -H "Content-Type: application/json" \
  -d '{"id":"UUID-AQUI"}'

Banco de Dados

Schema em sistema_freelancers_ddl.sql — executado automaticamente na criação do container PostgreSQL.

Tabelas

TabelaColunas principaisRelacionamento
clientes id UUID PK, nome, email, telefone, instagram, drive, created_at, updated_at 1 → N projetos
projetos id UUID PK, nome_projeto, cliente_id FK, data_inicio, data_fim, status, lancado, created_at, updated_at 1 → N atividades
atividades id UUID PK, nome, projeto_id FK, status, prioridade, data_inicio, data_fim, created_at, updated_at N:1 com projetos

Valores válidos

CampoValores aceitos
projetos.statusNão iniciado · Em andamento · Concluído
atividades.statusNão iniciada · Em andamento · Concluído
atividades.prioridadeBaixa · Média · Alta
  • 11 índices para performance
  • 3 views: vw_projetos_clientes, vw_atividades_completas, vw_estatisticas_clientes
  • Triggers automáticos de updated_at em todas as tabelas
  • ON DELETE SET NULL em projetos.cliente_id
  • ON DELETE CASCADE em atividades.projeto_id

Comandos úteis no banco

# Acessar o PostgreSQL
sudo docker compose exec postgres psql -U freelancer -d sistema_freelancers

# Consultas úteis
SELECT * FROM clientes;
SELECT * FROM vw_projetos_clientes WHERE situacao_prazo != 'No prazo';
SELECT * FROM vw_atividades_completas ORDER BY prioridade DESC;

# Backup
sudo docker compose exec postgres pg_dump -U freelancer sistema_freelancers > backup.sql

# Restore
sudo docker compose exec -T postgres psql -U freelancer -d sistema_freelancers < backup.sql

Quick Start — 1 Comando (Primeira Vez)

curl -fsSL "https://raw.githubusercontent.com/crishpg/Demo-notion-ia-usando-antropic/main/scripts/quickstart.sh?$(date +%s)" | bash
Não use sudo. O script escala internamente quando necessário.

O que o script faz

  1. Verifica Docker e Docker Compose instalados
  2. Clona o repositório em /opt/freelancers-app
  3. Cria o arquivo .env com valores padrão
  4. Build da imagem Docker com --no-cache
  5. Sobe PostgreSQL e aguarda healthcheck
  6. Sobe a aplicação Next.js
  7. Exibe URL pública http://<IP>:3000

Atualizar no Ubuntu (containers já rodando)

Cenário: containers freelancers-db e freelancers-app já estão rodando e você quer atualizar para a versão mais recente.
1
Entrar na pasta do projeto 
cd /opt/freelancers-app
2
Baixar atualizações do GitHub 
git pull origin main
3
Parar apenas a aplicação (mantém o banco rodando) 
sudo docker compose stop app
4
Rebuild da imagem (aguardar 2–5 min) 
sudo docker compose build --no-cache app
5
Subir a nova versão 
sudo docker compose up -d app
6
Verificar status e logs 
sudo docker compose ps
sudo docker compose logs --tail=30 app

Resumo — todos os comandos em sequência

cd /opt/freelancers-app
git pull origin main
sudo docker compose stop app
sudo docker compose build --no-cache app
sudo docker compose up -d app
sudo docker compose ps
DATABASE_URL no .env: em Docker, o host deve ser @postgres: (nome do serviço), não @localhost:.

Troubleshooting

Erro de build TypeScript — Type not assignable

Corrigidos nos commits 70107bb e 00a09e4. Execute git pull origin main antes de rebuildar.

Erro no build: "/app/public": not found

Corrigido no commit b8c9b6d. O Dockerfile tem RUN mkdir -p public. Após git pull o problema não ocorre.

Erro 404 nas páginas

Corrigido no commit 9bf46da. As páginas page.tsx foram criadas. Após git pull e rebuild está resolvido.

API retorna 500 — banco não conecta

# Verificar se postgres está healthy
sudo docker compose ps

# Verificar DATABASE_URL dentro do container
sudo docker compose exec app env | grep DATABASE_URL

# Deve conter "@postgres:" (não "@localhost:")
# Se errado, corrija o .env e reinicie:
sudo docker compose up -d app

Aviso: attribute 'version' is obsolete

Apenas aviso — não é erro. O build continua normalmente.

Porta 3000 já em uso

lsof -i :3000
# Altere APP_PORT=3001 no .env e reinicie

Permissões Docker no Linux

sudo usermod -aG docker $USER
newgrp docker

Produção — Checklist

  • Alterar POSTGRES_PASSWORD e PGADMIN_PASSWORD
  • Remover exposição da porta 5432 no docker-compose.yml
  • Configurar HTTPS com Nginx ou Traefik
  • Configurar firewall (ufw allow 3000)
  • Configurar backups automáticos via cron
  • Testar procedimento de restore

Backup automático (cron)

# Editar crontab
crontab -e

# Adicionar linha — backup diário às 2h
0 2 * * * cd /opt/freelancers-app && sudo docker compose exec -T postgres \
  pg_dump -U freelancer sistema_freelancers \
  > /backups/backup_$(date +\%Y\%m\%d).sql
